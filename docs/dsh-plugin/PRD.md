# DSH 决策笔记插件：产品需求

- 日期：2026-10-28。
- 状态：R-01 至 R-12 已实现；综合运行证据与最终验收见 [验证记录](./VALIDATION.md)。
- 任务入口：[TODO](./TODO.md)。技术方案：[IMPLEMENT](./IMPLEMENT.md)。
- 本轮交付：插件源码、完整构建资源、回归测试、安装与配置说明；现有 GUI 的测试接入单独记录，不发布 npm 或推送远端。

## 1. 问题与目标

当前项目把决策笔记的方法、模板、校验脚本和单文件看板打包为通用 skill。使用者仍需为各项目安装或配置 skill、补充提醒规则，再手动生成看板并在浏览器中选择目录。新会话能否遵守笔记约定，依赖各项目的接入情况。

目标是在 DSH 的 Web profile 中安装并启用一次插件，使该 profile 下各工作区的会话自动获得 skill 和简短规则，并能在会话中查看所属项目实时更新的决策笔记。笔记继续保存在项目文件中，沿用 Git 和现有编辑方式。

## 2. 已确认的产品决定

| 编号 | 决定 | 约束 |
| --- | --- | --- |
| D-01 | 在每个会话的【对话】【轨迹】旁新增【决策看板】 | 使用原生会话页签，接受空白会话尚未开始对话时隐藏页签的现有行为。 |
| D-02 | 自动注入简短规则，重要改动时加载完整 skill | 机械性小改跳过，不默认注入完整 skill 或全量历史笔记。 |
| D-03 | 笔记维护跟随开发任务授权自动完成 | 不增加独立的笔记确认门；真正待定且影响任务方向的技术决策才询问用户。 |
| D-04 | 默认使用项目根下的 `.agents/notes/` | 可按工作区配置其他目录，仍遵循同一套笔记格式。 |
| D-05 | 看板以只读浏览为主 | 支持把选中笔记的引用加入当前会话草稿，由用户补充要求后发送。 |
| D-06 | 自动校验，要求 agent 修复本次引入的相关错误 | 历史问题和来源不确定的问题单独报告，不新增系统强制结束门禁。 |
| D-07 | 保留原看板的主要布局和功能，适配 DSH 主题 | 支持明暗主题，调整字体、颜色和尺寸。 |

入口已经确定为会话页签。早期评估中的“独立工作区页签”“工作区标题按钮”“全局中央看板入口”不属于本版方案，因此不需要为这些入口修改 DSH 宿主，也不需要无会话工作区专用的数据接口。

## 3. 用户与主要场景

### 3.1 在新项目开始开发

1. 用户在已启用插件的 Web profile 中添加工作区并开始会话。
2. agent 自动获得简短规则和可用 skill 目录，无需向项目复制 skill 或手改项目规则。
3. 尚未发送第一条消息时，页签沿用 DSH 的空白会话行为；会话开始后出现【决策看板】。
4. 项目尚无笔记时，看板显示空状态。查看看板和后台校验不创建目录。
5. 第一次遇到应记录的决策时，agent 按已授权任务创建必要目录和笔记。

### 3.2 在已有工作区开启新会话

1. 新会话自动获得同样的规则与 skill。
2. agent 在非平凡改动前检索该项目已有决策，优先更新有归属的笔记，避免重复起篇。
3. 用户打开看板时，看到同一工作区已有笔记；各会话保留各自的筛选、阅读和滚动状态。

### 3.3 开发与阅读同时进行

1. agent 或外部编辑器新增、修改、删除、归档笔记。
2. 看板自动更新列表、正文、统计和关联。
3. 校验结果区分本次引入、历史已有和来源不确定的问题。
4. agent 在完成任务前检查最新结果，修复本次引入的相关问题，并报告其余缺口。

### 3.4 围绕一篇笔记继续讨论

1. 用户在看板选中笔记，点击“加入当前会话”。
2. 插件把标题和可定位引用插入本会话的草稿，保留已有文字、引用和附件。
3. 用户补充要求并发送。插件不自动发送消息。
4. 若读取过程中切换了会话，旧操作取消，不能将引用插入另一个会话。

## 4. 功能需求与验收标准

本表的 R 编号用于关联实现与任务，不另建一套重复编号。

| 编号 | 需求 | 可观察的验收标准 |
| --- | --- | --- |
| R-01 | Web profile 内一次启用 | 在同一 Web profile 的新工作区和已有工作区的新会话中均能使用 skill 与看板；接入不要求项目安装 skill、修改项目规则、npm scripts 或 CI。其他 profile 不在默认覆盖承诺内。 |
| R-02 | 原生会话看板页签 | 【决策看板】与【对话】【轨迹】并列，切换不丢会话；接受宿主空白会话隐藏规则；无需修改宿主。 |
| R-03 | 简短规则与按需 skill | 兼容会话自动得到简短规则，非平凡改动加载完整 skill，纯机械改动跳过；模型上下文不默认包含全量历史。可识别实际 skill 来源与不可用原因。 |
| R-04 | 跟随授权的笔记流程 | agent 在任务授权内检索、起草、更新、流转、归档和校验笔记，不因 skill 的通用确认要求反复停下；尊重用户指令和项目约束，真正待定决策仍询问用户。 |
| R-05 | 项目本地存储与路径覆盖 | 默认解析工作区项目根下的 `.agents/notes/`，支持按工作区覆盖目录；检索、写入、归档、校验和看板使用同一个根。读取不隐式建目录，不迁移已有 ADR，不跟随 agent 的临时工作目录切换项目。 |
| R-06 | 保留看板浏览能力 | 包含总览、时间线、避坑清单、文档目录、搜索、状态与类别筛选、关联及全文阅读。功能与原看板主要能力对应，提供明暗主题适配及空态、加载、错误状态。 |
| R-07 | 安全回填会话草稿 | 使用宿主公开接口插入引用，保留原草稿、引用芯片和附件；草稿变更、提交中、会话切换等情况下可拒绝或取消；不退化为覆盖全文，不自动发送。 |
| R-08 | 文件变更实时可见 | agent、shell 或外部编辑器产生的增删改、归档，以及目录首次创建、删除重建、checkout 后能自动同步；重连后恢复完整状态，不以旧结果覆盖新结果。更新延迟在集成阶段实测记录。 |
| R-09 | 自动校验与保守归因 | 目录、格式、相对链接、归档封印等现有校验自动运行；基线完整且有操作证据时识别本次引入的问题；历史与来源不确定的问题单列。agent 收尾检查覆盖最后一次相关修改的结果，不以过期成功状态代替。 |
| R-10 | 多工作区与多会话隔离 | 不同工作区不串文档、配置、校验结果或草稿。同一工作区共享笔记快照，各会话保留独立浏览状态；不同 Git worktree 按各自项目路径处理。 |
| R-11 | 保留通用 skill 和独立工具 | 现有通用 skill 的独立复制/符号链接安装、CLI 校验、归档、看板初始化与打包继续可用；无需依赖插件源码目录或 DSH 运行时。 |
| R-12 | 兼容性与运行状态可解释 | 声明经验证的 DSH 版本和 Web profile 范围；同名 skill 遮蔽、skill 工具不可见、完整自定义 prompt 等影响能说明。切换、卸载、重连正确取消订阅；文档正文与链接经过安全处理。 |

## 5. 笔记流程约定

- 非平凡改动包括行为、架构、跨文件契约、流程工具、测试策略、落盘/网络/配置格式等有持续决策价值的变化。
- 已有笔记承担相关决定时优先就地维护；新决定按 `proposed`、`implemented`、`rejected`、`archived` 和既有六类组织。
- 决策或核心理由发生翻转时，保留必要的新旧关联和历史依据，不把旧决定改写成相反结论。
- 任务授权包含与任务有关的笔记维护，不扩大成无关历史笔记清理。后台校验本身只读，不能自动重写归档封印来消除报错。
- “要求 agent 修复”是已选工作流程。插件不承诺从技术上阻断所有任务结束、Git 提交或外部修改，也不能单凭格式校验判断所有遗漏的决策记录。

## 6. 数据与边界

项目 Markdown 是事实来源，归档清单沿用现有机制；缓存、搜索索引和校验基线都是可重建的辅助状态，不替代项目文件。初次查看、安装启用、读取失败均不能隐式写项目。

目录覆盖用于调整存放位置，不自动识别或转换任意 ADR 格式。权限校验、路径解析和默认限制见 [IMPLEMENT 的工作区绑定](./IMPLEMENT.md#4-工作区绑定与根目录)。

“本次引入”必须建立在可靠基线和变更证据上。并发、分支切换、配置或规则版本变化、基线缺失等情况下，允许报告来源不确定；不能为了给出确定标签而归责当前会话。

## 7. 本版范围外

- 独立于会话的工作区页签、工作区标题按钮及无会话看板。
- 看板内直接编辑、新建、删除笔记或执行状态流转。
- 自动迁移项目现有 ADR、批量修复历史笔记或生成全量历史摘要。
- 系统级强制提交/任务完成门禁、接管 shell Git 行为。
- 默认覆盖 headless、ACP、SDK 等其他 profile，以及未验证的外部 agent 后端。
- npm 发布、正式长期部署或推送远端；本轮运行验证采用可撤销的本地 profile 接入。
